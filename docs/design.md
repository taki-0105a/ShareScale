# ShareScale の設計

> This document describes ShareScale's design (threat model, protocol, storage, distribution, diagnostics) in Japanese. An English summary of the security design is in the Security section of [README.md](../README.md).

この文書は、ShareScale の作りのうち、安全に関わる部分（脅威モデル・通信・ペアリング・保管・配布・自己診断）をまとめたものです。使い方は [README.ja.md](../README.ja.md) にあります。

## 言葉

| この文書の言葉 | 意味（画面の言葉） |
|---|---|
| 見る側 | 画面共有で相手を見ている Mac で動く `ShareScale.app`（画面では「接続元の Mac」） |
| Host | 画面共有で操作される Mac で動く常駐 `ShareScale Host.app`（画面では「接続先」「この Mac の接続先」） |
| 倍率 | 画面共有の仮想ディスプレイの描画倍率（画面では「表示倍率」。1x 等倍／2x Retina） |
| ペアリング | 見る側と Host が秘密の値を共有すること |
| 記録 | ログ |

## 目的と対応範囲

- 画面共有（高パフォーマンス接続）の仮想ディスプレイの倍率（1x／2x）を、見る側のディスプレイに合わせて保つ。利用者は 2 台の Mac に同じアプリを入れてペアリングするだけで使え、導入（Homebrew と Command Line Tools）を除き、SSH・ターミナル・管理者の権限が要らない
- Apple シリコン、macOS 14 Sonoma 以降（動作を確かめているのは macOS 27 だけ）。ローカルネットワークの許可は macOS 15 以降にだけある
- 範囲外: 画面共有そのものの起動・操作・設定、ファイアウォールの設定の変更（状態を診断して案内するだけ）、ターミナルから使うコマンド

## 脅威モデル

守るもの: Host の Mac の画面設定（倍率）と、ペアリングの秘密の値。Host ができることが少ないため、破られた時の被害もそこまでに限られる。

**規則: Host への指示は、倍率の設定（`set`）と、状態・記録の読み取り（`status`・`log`）に限る。ほかに許すのは、ペアリングのための名乗り（`hello`・`reveal`）と、見る側が自分のペアリングを解除する `unpair` だけ。任意のコマンドの実行や、任意のファイルの読み書きにつながる指示は加えない。**

- `unpair` の対象は、その接続で照合済みの自分の `id` だけ。名前やパスは受け取らない。秘密を盗んだ者ができるのは、そのペアリングを解除させることだけ

| 区分 | 相手 | 備え |
|---|---|---|
| 範囲内 | 同じ LAN・同じ tailnet にいる第三者（盗聴・なりすまし・mDNS の偽の応答・中継） | TLS-PSK と id の結び付け、名乗りの確認番号、送り元の分類と締め出し |
| 範囲内 | 接続コードを一時的に見た人（プロジェクター、画面の録画、同期されたクリップボードの履歴） | コードは 10 分・1 回限り。名乗りは Host での承認と確認番号の一致で完了 |
| 範囲内 | どちらかの Mac のほかの利用者（管理者でない） | 秘密はフォルダ 700・ファイル 600。自動の引き渡しは所有者と書き込み権を確かめてから |
| 範囲内 | グローバル IPv6 などでインターネットから届く相手 | 既定ではグローバルアドレスからは受け付けない（TLS の前に切る） |
| 範囲外 | 同じ利用者として動く悪意あるプログラム | 600 のファイルを読め、そもそも画面設定を直接変えられる |
| 範囲外 | root と管理者の利用者 | いつでも権限を上げられる |
| 範囲外 | FileVault が無効な Mac への物理的な接触 | 診断で FileVault の無効を注意するだけ |

**確認番号の安全性の前提**: TLS 1.2 の ekm（エクスポーターで作る値）が中継の両側で一致しないこと。これを支えるのは、見る側・Host の両方が相手の ECDHE の公開値を検証すること（X25519 はすべて 0 の共有値を拒否する。P-256 は曲線上の点かを検査する）。中継する者は両側の共有値を同じにできず、ekm は一致しない。Extended Master Secret（RFC 7627）は前提にしない（Network.framework には「EMS が無ければ断る」設定も、EMS が使われたかを読む公開 API も無いため）。この前提は必須の試験で両向きに確かめている（見る側が申し出る 4 つの曲線すべてで、小さい位数の点・範囲外の値・曲線外の点・無限遠点を両側が断る）。

配布の信頼の根は、tap と本体のリポジトリを持つ GitHub アカウントである（sha256 は tap が指す tarball を固定するだけ）。

## 構成

```
ShareScale.app（見る側の画面・設定・メニューバー）
└── Contents/Library/LoginItems/ShareScale Host.app（接続先の常駐。メニューバーのアイコン）
```

| 部品 | 役割 |
|---|---|
| ShareScale.app | 見る側のカードの画面、接続先の追加（ペアリング）、診断、設定、メニューバー。「この Mac を接続先にする」で Host をログイン項目に登録・解除する（`~/Applications/ShareScale.app` から）。Host の操作（一覧・解除・一時停止・接続元の Mac の追加・診断）も設定とメニューから行える |
| ShareScale Host.app | 接続先の常駐（ログイン項目。画面はメニューバーだけで、接続コードと名乗りの確認だけは自分のウインドウで出す）。通信の窓口、倍率の維持、ペアリングの受け付け |
| Host の子プロセス（`--apply-once`） | 倍率の変更を別のプロセスで行う（8 秒で打ち切り） |

ソースは SwiftPM のターゲットに分け、各部品は決めた依存だけを持つ（`ShareScaleProtocol`: 形式と検査の純粋な関数、`ShareScaleNet`: TLS の窓口と秘密の保管、`ShareScaleEngine`: 倍率の維持、`ShareScaleHostCore`／`ShareScaleHostUI`／`ShareScaleHost`: Host、`ShareScaleCore`／`ShareScaleUI`／`ShareScale`: 見る側）。**リモートの SwiftPM の依存（他人のパッケージ）は持たない**（利用者の Mac での組み立てを他人のコードに依存させないため）。暗号は Apple の実装（Network.framework・Security・CryptoKit）だけを使い、自前の暗号プロトコルは作らない。

```
見る側 ShareScale.app ──TLS（ペアリングの秘密で相互認証）──▶ Host の窓口 ──▶ 設定を保存 ──▶ 維持の判定 ──▶ 子プロセスで倍率を変更
                                                                         ▲ 画面構成の変化（通知）・2 秒ごとの点検
```

### 同じ Mac の中の受け渡し（ShareScale.app と Host）

- ファイル（`~/Library/Application Support/ShareScale/host-control/`。フォルダ 700・ファイル 600）と、中身を載せない通知（`DistributedNotificationCenter` の「読み直して」だけ）で行う。**ループバックの通信口は使わない**（認証の無い窓口を作らないため）
- 指示は `request-<uuid>.json`（厳密な JSON・4 KiB 以下。`pause`・`resume`（一時停止・再開）、`issue_code`（接続コードの発行）、`unpair`（登録の解除）、`snooze`（80 日使われていない知らせの先送り）、`set_tailscale_only`・`set_allow_global`（受け付けの設定）、`quit`（終了）、`show_code`・`show_diagnostics`（Host のウインドウを出す）の 10 個だけ）。Host は `at` が 5 分より古い・10 秒より未来のものを捨て、自分の起動より前に置かれた「終了」「接続コードの発行」を行わない
- 状態は Host が書く `state.json`（秘密・接続コードの文字列は載せない。コードは期限だけ）
- 秘密の値と接続コードはこの受け渡しに載せない。ShareScale.app から「接続元の Mac を追加」を頼んだ時も、コードは Host 自身のウインドウで表示する
- メニューバーのアイコンを 1 つにまとめるため、ShareScale.app は開いている間 `host-control/menubar-owner.json`（自分の pid）を書く。Host は、自分が健全で、その pid が今も ShareScale.app として動いている間だけ自分のアイコンを出さない（それ以外は出す。消えたままにならない方に倒す）

## ペアリング

### 操作

1. 接続先で ShareScale を開き「この Mac を接続先にする」をオン（Host がログイン項目に登録され、動く）
2. Host の「接続元の Mac を追加…」→ **接続コード**を Host のウインドウに表示（10 分間・1 回限り。新しいコードを出すと前のコードは無効）
3. 見る側の「接続先を追加…」にコードを貼り付ける（画面共有のクリップボードの共有／ユニバーサルクリップボード／手入力）
4. 見る側が名乗る（Mac の名前）。見る側と Host の両方に同じ **6 桁の確認番号**が出る
5. Host の確認のウインドウで、見る側の番号と同じなら「追加する」を押す

### 接続コード

- 形式: `sharescale1:` ＋ base64url（パディングなし）の JSON `{"v":1,"id":"<ペアリングID 16 バイトの hex>","k":"<秘密の値 32 バイトの base64url>","p":<ポート>,"a":["<候補アドレス>",…],"x":<有効期限 UNIX 秒>}`
- 秘密の値は見る側ごとに `SecRandomCopyBytes` で 256 ビット作る。短い数字の暗証番号は使わない（盗聴からの総当たりを防ぐため）
- 候補アドレス: Host の `<LocalHostName>.local` と Tailscale の IPv4（「Tailscale からの接続だけを受け付ける」の時は Tailscale の IPv4 だけ）。作れない時は Wi‑Fi・有線のプライベート IPv4 を 2 件まで
- 見る側の検査（満たさなければ接続を試みない）: 全体 1 KiB 以下、正しい base64url、下の「厳密な JSON」、`id` はちょうど 32 文字の小文字の hex、`k` は 32 バイト、`p` は 1〜65535、`a` は 1〜8 件のホスト名か書き直した形の IP の字句（`010.1.1.1`・`FD7A::1`・`::ffff:1.2.3.4`・ゾーン付き・最後のラベルが数字だけのホスト名などを拒否。表示と接続先を一致させ、名前解決での読み違いを防ぐため）
- 見る側は `x` で拒否しない（時計のずれで使えなくならないように）。期限を決めるのは Host の単調な時計
- コードの秘密は名乗りまでしか使えない（承認の時に新しい秘密へ取り替える）
- 手入力: アドレス（`<ホスト名>`・`<IPv4>`・`[<IPv6>]`、任意で `:<ポート>`）と、キー（ペアリング ID と秘密の 48 バイトを Crockford base32 にした 77 文字と検査文字 1 文字。4 文字ずつ区切って表示）。入力は NFKC で正規化する

### 名乗りと確認番号

コードを知っている人は誰でも正しい証明を作れるので、名乗りは **Host での承認**と **確認番号の一致**で完了させる。確認番号は TLS のセッションごとの値（ekm）から作るので、間に入って中継すると見る側と Host で番号が変わる。

1. 見る側: 乱数 `r_v`（32 バイト）を作り、`{"v":1,"op":"hello","name":…,"c":<SHA-256(r_v)>,"id":…,"proof":…}` を送る（`c` は `r_v` の約束）
2. Host: 証明を照合し、コードの期限と未使用を確かめ、**コードをこの時点で使用済みにする**。乱数 `r_h` を返す
3. 見る側: 同じ接続で `{"v":1,"op":"reveal","r":<r_v>}` を送る
4. Host: `SHA-256(r_v)` と `c` を定数時間で比べ、同じなら確認番号を計算して確認のウインドウを出す
5. Host は承認まで最大 60 秒（スリープ中も進む時計で）応答を保留する。承認されたら新しい秘密を作って保存し、返す。「追加しない」・時間切れ・約束の不一致・切断は失敗（保存しない）

- **確認番号** = `HKDF-SHA256(ikm: ekm, info: "ShareScale-sas-v1" ‖ 0x00 ‖ r_v ‖ r_h, 4 バイト)` を 1,000,000 で割った余りの 6 桁。見る側の乱数を先に約束させ、Host の乱数を後から混ぜるので、どちらの側も番号を選べない（TLS 1.2 ではクライアントが相手の鍵を見てから自分の鍵を選べるため、ekm だけからは作らない）。中継の成功は 1 回につき 100 万分の 1 で、コードは最初の名乗りで使用済みになる
- 確認のウインドウは「追加しない」を既定のボタンにする。名前は検査したもの、送り元は数字の表記だけを出す
- 名前の規則: NFC で 1〜64 文字・UTF-8 で 128 バイト以下。制御文字・書式文字（双方向の制御文字を含む）・行と段落の区切りを拒否。空白だけの名前も拒否

### 名乗りの後の確定と期限

- 見る側は受け取った秘密を保存したら、その秘密で `status` を送って確定させる（最大 3 回）。Host は承認から 10 分以内に新しい秘密で一度も照合できなかったペアリングを自動で解除する
- コードの期限と 10 分の自動解除は、Host の単調な時計（スリープ中も進む）で判定する。使われていないコードは記憶の中だけに置き、Host が終わると無効になる

### 保管

- 秘密は役割ごとに分ける: `~/Library/Application Support/ShareScale/pairings/host/`（この Mac の Host が受け入れる見る側）と `pairings/viewer/`（この Mac が使う接続先）。**Host は `host/` だけ、見る側は `viewer/` だけを読む**
- 1 ペアリングにつき、秘密 `<id>.key`（`{"format":1,"role","id","k","machine":<IOPlatformUUID>}`）と付帯情報 `<id>.meta`（名前・最終接続日時など）
- 読む時に、通常のファイル・所有者が本人・権限が 600 より緩くない・リンクが 1 本、フォルダも本人・700、`role` が置き場所と一致、`id` がファイル名と一致、`machine` がこの Mac と一致（移行アシスタントで別の Mac に写ったペアリングを使わない）をすべて確かめる。満たさなければ使わず、診断で案内する
- 書く時は、同じフォルダの一時ファイル（600、`O_CREAT|O_EXCL|O_NOFOLLOW`）に書いて fsync してから名前を変える
- 組の秘密は Host で作り、暗号化した名乗りの接続の中で接続元の Mac に 1 回だけ届ける（`reveal` への応答）。それ以外には送らない（その後は TLS の PSK として使うだけ）。接続コードの秘密は 1 回限りで、名乗りまでしか使えない
- `pairings/` はバックアップの対象から外す。キーチェーンは使わない（簡易署名では組み立て直しのたびに確認が出るため）。SSH の秘密鍵と同じく FileVault による暗号化を前提にし、無効なら診断で注意する
- 未使用の接続コードの秘密と `r_v`・`r_h` は記憶の中だけに置く。秘密の値・証明・ekm・確認番号は記録に書かない
- ペアリングの数は、Host は見る側 32 件、見る側は接続先 32 件まで

### 解除

- 見る側が接続先を削除する時は、まず `unpair` を送る。届かなければ見る側だけで消し、接続先でも解除するよう案内する
- 秘密のファイルは**削除する（ゴミ箱に移さない）**。`.key` を消してから `.meta` を消し、フォルダを fsync する
- 長く使われていない見る側（80 日）は知らせるだけで、自動では解除しない
- 解除したペアリングの接続中の通信は切る
- **エラーを理由にペアリングを自動で消さない**（TLS の警告は認証されないため、LAN の攻撃者が差し込める）

## 通信の窓口

### 接続

- Network.framework の `NWListener`／`NWConnection`、TCP、TLS。ポートは 47651。Bonjour で自分を知らせない
- 認証: TLS の事前共有鍵（PSK）。PSK ＝ペアリングの秘密、識別子＝ペアリング ID（乱数だけ）
- 方式: **TLS 1.2 の ECDHE-PSK（`TLS_ECDHE_PSK_WITH_CHACHA20_POLY1305_SHA256`、0xCCAC）だけ**。両側とも、接続が成立した時点で、読み書きの前に、交渉された版が TLS 1.2・方式が 0xCCAC であることを確かめ、違えば切る（受け側に 0xCCAC だけを設定しても、相手が ECDHE の無い PSK だけを出すとそれで成立してしまうため。確認番号の安全性は ECDHE に頼る）
- セッションの再開・チケット・再交渉・False Start を両側で使わない（TLS 1.2 の再開は PSK の確認を飛ばすため）

### 接続相手の確定（ペアリング ID の結び付け）

TLS の受け側は、どの PSK で成立したかを公開 API で読めない。そのため最初の指示に `id` と `proof` を付けて確かめる。

- `bindKey = HKDF-SHA256(ikm: 秘密, info: "ShareScale bind v1", 32 バイト)`
- `ekm = TLS エクスポーター（ラベル "EXPERIMENTAL-ShareScale-bind-v1", 32 バイト）`
- `proof = base64url(HMAC-SHA256(bindKey, "ShareScale-bind-v1" ‖ 0x00 ‖ id ‖ 0x00 ‖ ekm))`
- Host は、照合する時点の登録表から `id` の秘密を引き、`proof` を定数時間で照合する。合わなければ `not_paired` を返して切る。照合は接続ごとに最初の指示で 1 回行い、以後その接続に `id` を結び付ける

### 指示と応答

どれも改行で終わる UTF-8 の JSON 1 行。名乗り以外は 1 接続につき 1 往復。

| 指示 | 内容 | 使える秘密 |
|---|---|---|
| `hello` → `reveal` | 名乗り（上の「名乗りと確認番号」） | コードの秘密だけ |
| `status` | 名前・機種・一時停止・画面共有中か・倍率・仮想ディスプレイ・直近のエラー・最後に倍率を変えたのが自分かほかの見る側か・候補アドレス | 登録済みの秘密 |
| `set` | 倍率 `1x`／`2x`／`off` を設定し、反映を最大 3 秒待って状態を返す | 登録済みの秘密 |
| `log` | 最大 50 行（倍率の維持の行と、その見る側自身の出来事だけ。ほかの見る側の名前・送り元アドレスは含めない） | 登録済みの秘密 |
| `unpair` | そのペアリングを消す | 登録済みの秘密 |

- 失敗は `bad_request`・`unsupported_version`・`paused`・`busy`・`not_paired`。読めない・上限を超える・時間切れは応答せずに切る
- Host から来た文字列は、見る側が制御文字を除いてから表示する

### 厳密な JSON

指示（Host が検査）と応答（見る側が検査）の両方に当てる。字句の型を区別できる検査器で読み、`JSONSerialization` の数値の変換には頼らない。

- 正しい UTF-8・BOM なし。1 行は最初の `\n` まで。`\r` を含む・`\n` の後にバイトが続く → 拒否
- 最上位はオブジェクト。同じキーが 2 回・知らないキー → 拒否
- 整数・真偽値・文字列はその字句だけ（`true` を 1 に、`1.0` を整数に読まない）。base64url は決められた長さに復号できること
- 大きさ: 指示 4 KiB 以下、応答 16 KiB 以下

### 送り元の分類と受け付けるネットワーク

送り元は、**TLS を始める前に**、接続の相手のアドレスで判定する（IPv4-mapped IPv6 は IPv4 に直してから）。

| 分類 | 範囲 | 既定で受け付けるか |
|---|---|---|
| ループバック | 127.0.0.0/8、`::1` | はい |
| プライベート IPv4 | 10/8、172.16/12、192.168/16 | はい |
| リンクローカル | 169.254/16、fe80::/10 | はい |
| 共有アドレス（Tailscale の IPv4 を含む） | 100.64.0.0/10 | はい |
| ULA（Tailscale の IPv6 を含む） | fc00::/7 | はい |
| 同じネットワークのグローバル | Wi‑Fi・有線のインターフェースのアドレスとプレフィックス長で決まる範囲（IPv6 は /64 以上、IPv4 は /16 以上だけ） | はい |
| そのほかのグローバル | 上記以外 | **いいえ**（「インターネットからの接続も受け付ける」でオン） |

- 「Tailscale からの接続だけを受け付ける」: Tailscale のインターフェース（100.64.0.0/10 の IPv4 と fd7a:115c:a1e0::/48 の IPv6 を両方持つ utun）に受け側を結び付け、さらに送り元がその範囲であることを確かめる。見つからない時は受け付けない（全経路に戻さない）
- 受け付けない分類の接続は TLS の前に切り、失敗には数えない。診断に直近 24 時間の件数を出す
- 画面の受け付けの行（Host のメニュー・Host の診断・ShareScale のメニュー・設定の「この Mac の接続先」）は、受け付ける送り元を設定の 3 つの状態で言い分ける: 既定「ローカルネットワークと Tailscale からの接続を受け付けています」、「インターネットからの接続も受け付ける」がオン「インターネットを含むすべてのネットワークからの接続を受け付けています」、「Tailscale からの接続だけを受け付ける」がオン「Tailscale からの接続だけを受け付けています」（こちらがオンなら、もう一方の設定に依らない）。4 か所とも同じ行。既定の「ローカルネットワーク」は、上の表のプライベートとリンクローカルのアドレス（同じサブネットでなくても受け付ける）と同じネットワークのグローバルを指す

### 時間の上限と攻撃への備え

| 対象 | 上限 |
|---|---|
| TLS の手続き | 5 秒 |
| 最初の指示が届くまで | 5 秒 |
| 1 接続の全体（名乗り以外） | 10 秒 |
| 名乗り: 確認のウインドウを出すまで | 10 秒 |
| 名乗り: 承認待ち | 60 秒（スリープ中も進む時計） |

- 同時の接続は全体で 4 本まで、同じ送り元は 1 本まで。1 本は直近 24 時間に照合に成功した送り元のために空けておく。上限を超えた接続は TLS の前に切る
- 失敗（TLS の不成立・照合できる指示なしの切断・`not_paired`・版や方式の拒否など）が 60 秒に 10 回を超えた送り元は 5 分間受け付けない。これは総当たりへの対策ではなく（秘密は 256 ビット）、負荷と記録のあふれを防ぐためのもの
- 「一時停止」は倍率の維持を止め、`set` を断る（ほかの指示には応じる）

### 記録

- `~/Library/Logs/ShareScale/`。追記だけで書き、1 MiB を超えたら 1 世代だけ残して切り替える。1 行 256 バイトまで。Host が書く名前などは制御文字を除く
- 失敗・拒否は送り元と理由を書く（同じものは 1 分に 1 行にまとめる）。秘密の値・証明・ekm・確認番号は書かない

## macOS の権限

- **ローカルネットワーク（macOS 15 以降）**: 見る側の接続に許可が要る。拒否されていると接続は失敗せずに待ちになるので、見る側はこれを「届かない」と区別して案内する。許可は実行体の身元に結び付くため、簡易署名で組み立て直した後に聞き直されることがある
- **アプリケーションファイアウォール**: Host への着信はファイアウォールの判定を受ける（簡易署名の Host は「署名されたソフトウェアを自動的に許可」の対象にならない）。Host の診断は、sudo を使わずに `socketfilterfw` で状態を読んで案内するだけで、設定は変えない。Host がまだファイアウォールの一覧に無い時は、初めて接続を受けた時に、macOS が許可を求めることがある（macOS 27 で確認。待ち受けを始めた時点では出なかった。利用者が「許可」を押すまで、見る側は届かない）。見る側からは Host のファイアウォールは見えないので、届かない時に確認すること（主の窓の案内・接続先の追加の結果・診断の行）に、接続先のファイアウォールを確かめる 1 文を添える（文は 1 か所の定義）
- FileVault は `fdesetup status` で読む
- 外部コマンド: ShareScale（ShareScale.app と Host）が起こすのは、`/usr/sbin/netstat`（画面共有を受けているか）・`/usr/sbin/system_profiler`（機種名）・`socketfilterfw`・`fdesetup`（どちらも状態を読むだけ）・`/sbin/route`（見る側。届かない時に、ほかの VPN が経路を握っていそうかを見る）と、Host 自身（`--probe`・`--apply-once` の子プロセス）だけ。この一覧は試験で縛る

## 倍率の維持

- Host は選ばれた倍率を `~/Library/Application Support/ShareScale/engine.json`（600。一時ファイルから入れ替え）に保存し、画面構成の変化の通知と 2 秒ごとの点検で、画面共有の仮想ディスプレイを見分けて倍率を当てる
- 倍率の変更は別のプロセス（`--apply-once`。環境は最小限）で行い、8 秒で打ち切る。子プロセスには Host の版と CDHash を渡し、違えば（入れ替えの途中）何もせずに専用の終了コード 75 で終わる
- 設定した倍率がほかから繰り返し戻される時は、奪い合いとして案内する（ほかのアプリが変えている可能性がある、とだけ言う。相手を調べに行かない）

## 見る側

- 候補アドレスは、前回つながったものを先に試し、つながらなければ残りを 300 ミリ秒ずつずらして並行に試す（`.local` の名前解決が遅いため）。並行に試した接続は途中で打ち切らない（Host の失敗に数えられて自分を締め出さないため）。指示は選んだ 1 本にだけ送る
- 照合済みの `status` の応答でだけ候補を書き換える。利用者が手で直した候補は書き換えない
- Host が照合済みの応答で断った時（`set` への `paused`、`set`・`status` への `busy`）は、接続できない失敗として扱わない（直前が接続できない失敗だった時は、手元の古い状態を捨てる）。接続の状態（主の窓のバッジ・メニューバーの状態の行）・見出し・カードは直前の状態のままで、案内だけが理由を言う（一時停止なら、状態の行は「一時停止中（表示倍率を変更しません）」）。「接続できなくなった」の通知も出さない
- 同じ Mac の中の Host には、候補がこの Mac 自身を指す時、127.0.0.1 で先に試す
- クリップボード: Host はコードをクリップボードの履歴に残さない印（`org.nspasteboard.ConcealedType`・`TransientType`）を付けてコピーする。見る側は利用者の操作でだけ貼り付けを読み、ペアリングが成功してクリップボードがまだそのコードのままなら消す
- 通知（任意・既定はオフ。オンにした時に初めて macOS が許可を求める）には接続先の名前だけを出し、アドレスは出さない。ShareScale が前面にある時は出さない
- 通知がオンで、ほかの接続元の Mac による変更か接続できなくなったことを選んでいる時だけ、ShareScale が前面になく Mac が眠っていない間、60 秒ごとに `status` を取り直す（直前が失敗・低電力モードなら 300 秒ごと。眠りから戻って 60 秒は取り直さない）
- メニューバー: ShareScale は主の窓を閉じてもメニューバーに残り、ディスプレイごとの 1x／2x の切り替え・更新・接続先の切り替えができる。メニューを開いた時に取り直す。この Mac で Host が動いていれば、Host のメニューと同じ項目の「この Mac の接続先」の節を出し、その間は Host が自分のアイコンを出さない（上の「同じ Mac の中の受け渡し」）
- アプリのメニュー: 標準のメニューは macOS の言語で出る（Info.plist に英語と日本語を宣言する。アプリ自身の文言も同じ決まりで、優先する言語の並びの中の、日本語か英語の最初のもの。どちらも無ければ英語）。記録や診断に載せるエラーの文は、読める文の後ろに、言語に依らない種類と番号を括弧で添える。「ヘルプ」は公開のリポジトリを利用者のブラウザで開く 1 項目だけ（アプリから開く外のリンクはこれだけで、アプリ自身は外へ通信しない）。診断と完全な削除のウインドウは、「ウインドウ」のメニューに開く項目を出さない
- 設定の窓の高さは、タブの中身に合わせる（その窓のある画面に収まる上限まで。超える分はタブの中をスクロールする）
- 押せる部品は、VoiceOver やアクセシビリティの操作の「押す」でも押せる（画面の部品の試験で確かめる。この試験はアクセシビリティの木を読むもので、macOS 27 で確かめている。木を読めない環境では飛ばす）
- 初回のガイド: 接続先が無く、この Mac の接続先の役もオフで、ガイドを見た印も無い時だけ、主の窓の中にしたいこと（別の Mac を操作する／操作される側にする／両方）を尋ねるページを出す。設定 › 一般の「はじめに…」でもう一度開ける

## 自己診断

- 見る側の「診断…」: ローカルネットワークの許可 → 届くか → ペアリングが有効か → Host が動いているか → 画面共有中か → 仮想ディスプレイを見分けたか → 倍率が設定どおりか → 直近のエラー。✓／✗／?（不明）と対処、「結果をコピー」（秘密・証明は含めない。接続先の名前と id の先頭 8 文字、候補アドレスとポートは含める）
- Host の診断: 動作中／一時停止、受け付けの状態、ファイアウォール（オフ・許可・ブロック・まだ一覧に無い）、ログイン項目、ペアリング済みの見る側の一覧、読めないペアリングのファイル、FileVault、奪い合い、直近のエラー
- システム設定で直せるもの（ローカルネットワーク・ファイアウォール・ログイン項目・FileVault・通知）は、利用者の操作で該当するシステム設定を開ける

## 配布

- tap `taki-0105a/homebrew-tap` の formula `sharescale`。利用者は `brew install taki-0105a/tap/sharescale`
- formula は GitHub のリリースに**添付した tarball**（自動で作られるソースの圧縮ファイルではなく、sha256 が変わらないもの）を取得し、sha256 で照合してから、利用者の Mac で組み立てる（quarantine が付かないため Gatekeeper の警告が出ない）。tarball には `docs/` を入れない
- 組み立ては `scripts/build-sharescale.sh`。中の Host を先に簡易署名（ad-hoc・強化ランタイム）し、外の ShareScale.app を後で署名する（`--deep` は使わない）。両方の実行ファイルに組み立てた場所のパスが無いこと、アーキテクチャが 1 つであることを確かめる
- 版: `VERSION` は `x.y.z`（各 0〜99）。`CFBundleVersion` = x×10000 + y×100 + z（git の履歴が無い tarball からでも同じ値）。コミット ID は表示のためだけで、tarball では `BUILD_INFO` から読む
- Info.plist に言語を宣言する（`CFBundleDevelopmentRegion`＝`en`、`CFBundleLocalizations`＝`en`・`ja`。ShareScale.app と Host）。宣言が無いと、macOS は標準のメニューと部品を日本語の環境でも英語で出す
- 予備: リポジトリを取得して `scripts/build-sharescale.sh --install`（`~/Applications/ShareScale.app` に置き、置き終えたら `build/ShareScale.app` を消す。名前で開いた時に、置いた方が開くように。消しきれずに残ったものは、次の組み立ての始めに片付ける）

### `~/Applications` への複製と引き渡し

簡易署名のアプリを Homebrew の置き場所（`<prefix>/Cellar/sharescale/<版>/`）からログイン項目に登録すると、`brew upgrade` で旧版が消えた時に常駐が起動できなくなる。そのため、アプリは自分を `~/Applications/ShareScale.app` に複製し、**ログイン項目の登録・解除と完全な削除は複製だけが行う**。

- **Homebrew 側**（実体が `<prefix>/Cellar/sharescale/<版>/ShareScale.app` で、`<prefix>` が `/opt/homebrew` か `/usr/local`）は、複製を作る・置き換える・開くことだけを行って終了する。見る側としては動かない
- **それ以外の場所**（組み立て用のフォルダなど）から開かれたアプリは、見る側としては動かず、前面に出した確認のウインドウで案内して終了する。複製がリンクでなく・本人のもので・識別子が ShareScale で・版と署名を読める時は、既定のボタン「~/Applications の ShareScale を開く」で複製を開いてから終了する（複製を作る・置き換えることはしない。複製が動いていれば、開き直しを頼んで主の窓を出させる。`~/Applications` そのものがリンクの時は、ボタンを付けない）
- **引き渡しの条件**（Homebrew 側から複製を作る・置き換える時と、複製が Homebrew 側を開く時）: Homebrew 側のバンドルの中のすべての項目の所有者が本人で、グループ・他人が書けず、シンボリックリンクと ACL が無いこと。上位のフォルダは `/` まで、所有者が本人か root で、他人が書けないこと（グループの書き込みは gid 80 の時だけ許す）。満たさなければ自動では入れ替えず、予備の手順を案内する（Homebrew の持ち主がほかの利用者の `~/Applications` とログイン項目に自分のプログラムを入れることを防ぐ）
- 複製の置き換え: 動いている複製に終了を頼み（5 秒で終わらなければ中止）、`~/Applications` の一時的な名前に複製し（`~/Applications` は本人のもので、グループ・他人が書けず、書き込みを許す ACL が無い時だけ使う）、署名を要件 `identifier "io.github.taki-0105a.ShareScale" and cdhash H"<自分の CDHash>"` で確かめ、`renamex_np(RENAME_SWAP)` で不可分に入れ替える
- 複製の起動時: Homebrew 側の版が新しい（または同じ版で CDHash が違う）なら、条件を確かめ、試みを記録してから Homebrew 側を開いて終了する（同じ版と CDHash への引き渡しは 1 回だけ）。常駐している間に新しい版を見つけたら、「新しいバージョンがあります」と「ShareScale を終了して開き直す…」を出す
- ログイン項目: 複製は起動時、自分の CDHash と最後に登録した時の CDHash が違えば、解除 → 3 秒 → 登録で登録し直す。`requiresApproval`（利用者がオフにした）なら登録し直さずに案内する。formula の `post_install` からは登録しない
- 「ログイン時に ShareScale を開く」（`SMAppService.mainApp`）は既定でオフで、複製だけがオンにできる

## 完全な削除

`brew uninstall` だけでは複製・ログイン項目・秘密・設定が残り、Host が待ち受けを続ける。複製の設定 › 一般の「ShareScale を完全に削除…」は次の順に行う。

1. Host の登録を解除し、Host のプロセスが終わったことを確かめる（最大 10 秒。終わらなければ中止）。「ログイン時に ShareScale を開く」の登録も外す
2. 登録している接続先それぞれに `unpair` を送る（届かなければ一覧にして案内する）
3. `pairings/` の秘密のファイルを**削除する**（リンクをたどらずに開き、決まった形の名前だけを消す。秘密が 1 つでも残れば中止する。ゴミ箱に秘密を入れないため）
4. 残りの `Application Support`・ログ・環境設定・保存されたウインドウの状態をゴミ箱へ
5. `~/Applications/ShareScale.app` をゴミ箱へ
6. `brew uninstall sharescale` をコピーできる形で表示する（アプリからは実行しない）

複製の起動時に Homebrew 側が消えていたら、「ShareScale は Homebrew から削除されています。この Mac からも完全に削除しますか？」と尋ねる。
